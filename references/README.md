# Reference products

Teardowns of exceptional interfaces, with values extracted from the live products — computed
styles, CSS custom properties, measured row heights and durations — rather than recalled.

Use them twice:

1. **Before you design.** Read the file matching your archetype. It tells you what the products in
   this space actually do, at the level of numbers.
2. **After you build.** The comparison test in [`../system/7-critique.md`](../system/7-critique.md):
   screenshot a reference product beside your work and name three differences. This is the highest
   signal technique in the whole system, because it replaces "is this good?" — which you cannot
   answer in isolation — with "how does this differ from something known-good?", which you can.

**On copying.** These exist to transfer principles, not pixels. Imitating Linear's palette gives you
a Linear skin; understanding *why* its rows are 28px and nothing moves on hover gives you something
you can apply to a product Linear has never heard of. Cloning a proprietary interface is also a
legal problem, not just a design one.
