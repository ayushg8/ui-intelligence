# Styled component systems & full design-system kits

**Evaluated:** 2026-09 · **Challenged & corrected:** 2026-09-09 (see `## Challenge pass (2026-09)` at the end — five numbers were wrong, two tiers moved, eight libraries were missing). · **Researcher note:** The category split into three unrelated markets: (1) copy-in registries where you own the code — shadcn/ui now on Base UI by default since July 2026, plus Untitled UI React and Park UI; (2) npm-installed opinionated systems — Mantine, Chakra v3, HeroUI, Nuxt UI, Ant Design; (3) legacy enterprise sets running on inertia — MUI (still Material Design 2 in 2026), Bootstrap 5.3.8 (last release Aug 2025), Vuetify, Fluent. The interesting fact for an anti-vibecode corpus: shadcn's `dashboard-01` block — "Acme Inc." sidebar, four KPI cards reading $1,250.00 / 1,234 / 45,678 / 4.5% — is now a literal visual fingerprint appearing verbatim in thousands of AI-built apps. Escaping it is a four-token job, and I verified two real products that did exactly that.

**How to read the vibecode column.** It measures one thing: how identifiable the *default* output is. It does **not** measure whether you can escape — that is a separate axis, and it is governed by distribution model, not taste. Copy-in systems (shadcn, Untitled UI React, Basecoat) put every token in a file you own, so a `high` rating there is a to-do list. npm-installed systems (HeroUI, Ant, MUI, Vuetify, Flowbite) put the fingerprint inside a dependency, so a `high` rating there is a property of the product you are shipping. Read the two together: `high (as shipped) / low (after N changes)` is a completely different risk from a flat `high`.

## Recommendations by need
- **Default choice:** shadcn/ui — you own the code, it now defaults to Base UI, and every escape hatch is a file you already have. But treat `npx shadcn init` defaults as a starting sketch, not a design.
- **Best engineering:** Mantine — 460 contributors, 58 open issues on 31.7k stars (a genuinely low ratio), a real hooks library, `@mantine/schedule`, and `@mantine/mcp-server` shipped in v9.
- **Best visual quality out of the box:** HeroUI v3 — and that is exactly the problem; you are adopting someone else's finished aesthetic, and on inspection it is a well-executed iOS-2023 pastiche rather than a current one.
- **Best colour system:** Radix Themes — 12-step perceptual scales with automatic light/dark and alpha variants, designed against real contrast targets. Even if you never install it, steal the scale structure.
- **Non-React / server-rendered:** daisyUI or Basecoat UI (Tailwind classes, no JS framework) or Web Awesome (web components, works everywhere).
- **Angular:** Angular Material if you accept Material; Spartan UI if you want the shadcn idiom. This file had no Angular entry at all before the challenge pass, which was an omission, not a judgement.
- **Best accessibility:** React Spectrum (Adobe employs the React Aria maintainers — everything else in this file that claims React Aria a11y is consuming their work) and Fluent UI React v9 (shipped by a team with legal a11y obligations). Base UI is the best a11y substrate if you are building your own.
- **Most customizable / least house-style:** Base UI, then Park UI's Panda recipes, then Chakra v3's recipe/slot-recipe system.
- **Lightest:** daisyUI — CSS-only, no JS runtime, no React dependency at all.
- **Promising newcomer:** Basecoat UI — created Jan 2025, 4,287★, MIT, 19.9k wk npm. It is shadcn's component vocabulary for people who are not in React, which is the gap nothing else in this file fills. (Untitled UI React held this slot before the challenge pass; its 4.9k wk CLI adoption does not support it.)
- **Premium/paid worth it:** Untitled UI PRO ($349 lifetime, per their pricing page — note this is the actual product; the MIT library is the funnel) if your team already lives in the Untitled UI Figma kit — design/code parity is the actual product. Nuxt UI Pro is no longer a purchase; it merged into the free package at v4.

## Scorecards

### shadcn/ui — `essential`
- **What:** A CLI + registry that copies component source into your repo. Since July 2026 `npx shadcn init` scaffolds on **Base UI** rather than Radix. *(Corrected 2026-09-09: it is now **three** primitive families, not two — `components.json`'s `style` enum carries `radix-*`, `base-*` and **`aria-*`** (React Aria) variants, each in eight named styles: vega, nova, maia, lyra, mira, luma, sera, rhea, plus legacy `default` and `new-york` — 26 values total, verified against `ui.shadcn.com/schema.json`.)*
- **Verdict:** Correct architecture, and the reason it wins is that there is no upgrade treadmill — the code is yours. It is also, unambiguously, the visual signature of AI-generated UI in 2026, and pretending otherwise helps nobody. The failure mode is not the components; it is that agents accept `--radius: 0.625rem`, a zinc/neutral ramp, `Card` as the answer to every container, and `dashboard-01` verbatim. The fix is small and specific (below), and two products I inspected prove it works.
- **Use when:** Any greenfield React product where you intend to own your design language. · **Don't use when:** You need a data grid, a scheduler, or 60 form controls tomorrow and have no design capacity — Mantine or PrimeReact will finish faster.
- **Scores /5:** visual 3 · interaction 4 · a11y 4 · engineering 5 · maintenance 5 · docs 5 · customization 5 · perf 5 · stability 4 · originality 5
- **Evidence (re-verified 2026-09-09):** ★123,460 · last release `shadcn@4.21.0` 2026-09-04 · last push 2026-09-10 · 8,742,877 wk npm (`shadcn` CLI) · 469 contributors · MIT · 1,963 open issues. Every figure confirmed against the GitHub and npm APIs; nothing stale. Used by **midday.ai** — verified: `packages/ui` carries the exact shadcn component roster and three shadcn references in code.
- **Looked at:** `ui.shadcn.com`, `/blocks`, `/docs/components/card`, plus `midday.ai` and `dub.co` as production comparisons. The docs site has quietly moved *off* its own default — buttons and inputs there are near-pill, the palette is pure greyscale, and there is a new `Typeset` section. Meanwhile `/blocks` still leads with `dashboard-01`: "Acme Inc." with a circle-outline logo, a black pill "Quick Create", and four KPI cards reading Total Revenue **$1,250.00** / New Customers **1,234** / Active Accounts **45,678** / Growth Rate **4.5%** with `+12.5%` trend chips. Those four numbers are the fingerprint. On `midday.ai` the same component library renders as a transitional **serif** display face, **zero** border-radius on the primary CTA, a warm off-white ground and a monochrome grain hero — nothing reads as shadcn. On `dub.co`, `@dub/ui` is Radix + `class-variance-authority` with **zero** shadcn references: a bespoke grotesk, ~8px radius, a faint architectural grid ground, and colored icon chips (violet/green/orange) as the only saturation.
- **The four changes that break the tell** (in impact order): **1. Radius.** `0.625rem` on everything is the loudest signal — go to `0` or `0.25rem` or `9999px`, just not the default. **2. Typeface.** Ship a real display face; the Geist/Inter default is half the fingerprint. **3. Ground.** `oklch(1 0 0)` pure white plus zinc borders is the AI look; move to a warm or cool off-white and drop border contrast. **4. Stop reaching for `Card`.** Default shadcn wraps every region in a bordered rounded box; strong products use rules, spacing and background shifts instead. A fifth, optional: add one token shadcn does not have (a grain, a signature easing, a named elevation) and use it everywhere. **A sixth, added 2026-09-09:** do not init on `new-york`. There are now eight authored styles per primitive family; picking `base-nova` or `aria-sera` moves you off the fingerprint everyone recognises — but be clear-eyed that it moves you into a smaller shared fingerprint, not to originality. The four changes above still do the real work.
- **Vibecode risk:** **high** as shipped — the default theme and blocks are the reference image for "AI-generated". Drops to low once radius, type, ground and card usage are authored. Never let an agent run `shadcn add` and ship without a `DESIGN.md`-style token contract.
- **Link:** https://ui.shadcn.com

### Mantine — `essential`
- **What:** A complete npm-installed React system: 100+ components, a large standalone hooks library, forms, charts, dates, notifications, rich text, and now scheduling.
- **Verdict:** The best-engineered thing in this category and it is not close. 58 open issues against 31.7k stars and 460 contributors is a maintenance signature you almost never see at this scale, and v9 (March 2026) shipped `@mantine/schedule` plus an official `@mantine/mcp-server`. Visually it is competent rather than opinionated — which is the good failure mode: Mantine looks like a well-made component library, not like a brand you have to fight. The Styles API (per-element class targeting on every component) makes retheming tractable in a way MUI's `sx` never quite is.
- **Use when:** Internal tools, dashboards, admin, data-heavy B2B, or any React app where component breadth beats visual signature. · **Don't use when:** You want the design language to be the product's differentiator — you will end up overriding a lot.
- **Scores /5:** visual 3 · interaction 5 · a11y 4 · engineering 5 · maintenance 5 · docs 5 · customization 4 · perf 4 · stability 5 · originality 3
- **Evidence:** ★31,692 · last release 9.6.1 2026-09-09 · last push 2026-09-09 · 2,233,927 wk npm (`@mantine/core`) · 460 contributors · MIT · 58 open issues
- **Looked at:** `mantine.dev/core/button` — every component page carries a live variant/color/size/radius playground plus an explicit **"LLM documentation"** link and a floating LLM-copy panel, which is a real DX advantage for agent workflows. The default filled button is Open Color `blue.6` (#228be6) at ~4px radius with a 10-swatch palette grid; that blue and that radius are the Mantine tell. Typography is a clean geometric sans with genuinely good vertical rhythm in the docs. Nothing decorative anywhere.
- **Vibecode risk:** medium — a default Mantine app is identifiable by the blue and the small radius, but it does not carry the cultural "AI slop" association shadcn does, and `theme.primaryColor` + `defaultRadius` + `fontFamily` neutralises most of it in three lines.
- **Link:** https://mantine.dev

### Base UI — `essential`
- **What:** Unstyled, accessible React primitives from the MUI team. Now the default primitive layer for new shadcn/ui projects.
- **Verdict:** This is the substrate the whole category has already converged on. 11M weekly downloads is not "converging"; it is done. Its component list already exceeds what Radix shipped — Autocomplete, Combobox, Drawer, Context Menu, Fieldset, Field. Single package, tree-shakable, explicit portal/isolation guidance, and first-class llms.txt. It is not a design system and should never be tiered against one; include it because "which styled kit" is increasingly answered by "none, Base UI plus our tokens."
- **Use when:** You have a designer or a real token system and want zero inherited aesthetic. · **Don't use when:** Nobody on the team will write the CSS — you will end up with worse defaults than any kit here.
- **Scores /5:** visual n/a · interaction 5 · a11y 5 · engineering 5 · maintenance 4 · docs 5 · customization 5 · perf 5 · stability 4 · originality 4  *(maintenance 5→4: 435 open issues on a 10.9k-star repo is a real backlog, and the earlier scorecard did not record the issue count at all.)*
- **Evidence:** ★10,869 · v1.8.0 2026-09-04 · last push 2026-09-09 · **10,994,876 wk npm** (`@base-ui/react`) · MIT · created 2024-02-23 · 435 open issues
- **Number correction (2026-09-09):** the earlier figure of 429,187 came from `@base-ui-components/react`, which was **renamed at 1.0** and is frozen at `1.0.0-rc.0` (2025-12-04). The live package is `@base-ui/react` at **11.0M weekly** — more than `@mui/material` (8.9M), more than every styled kit in this file combined. Verified against the npm registry on 2026-09-09. This is why the tier moved from `strong` to `essential`: it is no longer a promising substrate, it is *the* substrate.
- **Looked at:** `base-ui.com/react/overview/quick-start` — the most restrained docs page in this whole set: no hero, no gradient, one accent, generous measure, a "View as Markdown" affordance and an llms.txt entry in the sidebar. Code blocks use a light-grey chrome with tab-style package-manager switching. It reads like documentation written by people who did not want to sell anything.
- **Vibecode risk:** none — it ships no visual opinion at all.
- **Link:** https://base-ui.com

### Untitled UI React — `situational`
- **What:** MIT open-source React components built on Tailwind CSS v4 + React Aria, from the team behind the Untitled UI Figma kit. Paid PRO tier adds hundreds of application/marketing components and 250+ page examples.
- **Verdict (revised 2026-09-09, demoted from `strong`):** The component-level craft is real — the secondary button's border/shadow/label-weight balance, the focus rings, the form-field anatomy are better resolved than shadcn's defaults, because they were drawn in Figma first by people who do this for a living, and React Aria underneath means the a11y is genuinely good rather than claimed. Three things the earlier pass under-weighted. **(1) Adoption is thinner than Once UI's.** `@untitledui/react` is deliberately unpublished (`"private": true`, version `0.0.0` in the repo's own package.json); distribution is the `untitledui` CLI, which does **4,913 weekly downloads** — *below* Once UI's 6,837, a number the earlier pass called "brutal" and used to justify an `experimental` tier. Applying that standard consistently moves this to `situational`. **(2) The library is a funnel.** The homepage carries "Buy now" twice above the fold; the $349 PRO kit is the product. That is the exact incentive read this file uses to put Flowbite at `reference-only`. **(3) The house style is more generic than "designer-authored" implies** — see Looked at.
- **Use when:** Your team already designs in the Untitled UI Figma kit, or you want React Aria ergonomics with real design taste on top. · **Don't use when:** You need a distinctive brand voice — you will be adopting a widely-recognised template look.
- **Scores /5:** visual 3 · interaction 4 · a11y 5 · engineering 4 · maintenance 4 · docs 4 · customization 4 · perf 4 · stability 3 · originality 2  *(visual 4→3 and originality 3→2 after screenshotting it myself; component craft is a 4, the composition is a 2.)*
- **Evidence:** ★1,911 · 9 open issues · created 2025-07-15 · last push 2026-09-02 · MIT (open core) · PRO $349 lifetime per their pricing page · **distribution settled 2026-09-09:** the repo's `package.json` is `"name": "@untitledui/react", "version": "0.0.0", "private": true` — it is never published by design. Real npm surface is the `untitledui` CLI (**4,913 wk**) and `@untitledui/icons` (**304,138 wk**). The icon library out-ships the component library 62:1, which tells you where the actual adoption is.
- **Looked at (screenshotted 2026-09-09, 1440 + 390):** `untitledui.com/react` — and my eyes disagree with the earlier read. This is the canonical 2023–2025 SaaS landing page: pure-white ground, faint dotted grid, centred grotesk headline, two hairline-bordered icon+label secondary buttons flanking a #7F56D9 violet "Buy now", tilted screenshot stack below the fold, fake collaborator cursor labelled "Olivia Rhye". Nothing on the page is a decision; every element is the default choice for its slot. The secondary-button anatomy really is better balanced than shadcn's — that part of the earlier note holds — but the *composition* is a template, and this is the specific template that v0/Lovable emit for marketing pages. Praising it as "designer-authored" was inherited praise, not observed praise.
- **Vibecode risk:** **high** as shipped (raised from medium-high) — violet-600 + grey ramp + dotted grid + tilted screenshot stack is a four-tell combination and it is the same combination AI page-builders emit by default. Drops to **low** once you re-token it, because — unlike HeroUI or MUI — the files are yours. Swap the violet, flatten the shadow scale, kill the dotted grid.
- **Link:** https://www.untitledui.com/react

### Chakra UI v3 — `strong`
- **What:** A ground-up rewrite: component logic moved to Ark UI (state machines via Zag), styling to a Panda-derived engine, with recipes and slot recipes as the theming unit.
- **Verdict:** The best *architecture* for theming of any npm-installed system here — recipes give you a real variant contract rather than a pile of style overrides, and the v3 token/semantic-token split is genuinely well designed. 16 open issues on 40.6k stars is remarkable, and Q1 2026 shipped a rich-text-editor composition plus automated v2→v3 migration. The cost is that v3 broke a lot of v2 code and the ecosystem's collective memory is still v2, so LLM-generated Chakra is frequently wrong-version.
- **Use when:** You want an installed system but intend to build a real design language on top of it. · **Don't use when:** You are leaning on an agent to write most of the UI — it will produce v2 syntax.
- **Scores /5:** visual 3 · interaction 4 · a11y 4 · engineering 5 · maintenance 5 · docs 4 · customization 5 · perf 4 · stability 4 · originality 3
- **Evidence:** ★40,638 · last release `@chakra-ui/react@3.37.0` 2026-08-28 · last push 2026-09-09 · 1,537,398 wk npm · 413 contributors · MIT · 16 open issues
- **Looked at:** `chakra-ui.com` — a teal-600 primary against near-black text, a large translucent lightning-bolt watermark, and a component showcase row of thin-bordered near-square cards. The site itself makes the architecture legible with a "Chakra / Ark / Zag" tab demo, which is an honest bit of docs design. The default component look is flatter and squarer than v2's; the teal is the tell.
- **Vibecode risk:** medium — recognizable by the teal and the flat 1px-border card, but the recipe system means a serious team escapes it completely.
- **Link:** https://chakra-ui.com

### Nuxt UI v4 — `strong`
- **What:** Vue/Nuxt component library on Reka UI + Tailwind. As of v4, Nuxt UI Pro was merged into the free package: 110+ components, 12 templates, and the full Figma kit, all MIT.
- **Verdict:** The clear default for Vue and Nuxt in 2026, and the Pro merge (enabled by NuxtLabs joining Vercel) removed the only real objection. Reka UI underneath gives it a genuine headless a11y foundation — the same architectural bet shadcn made with Radix/Base UI, three years later and better executed for Vue. 257 open issues is higher than I'd like for a 6.9k-star repo but the release cadence (v4.11.1 two days before I checked) is healthy.
- **Use when:** Any Vue or Nuxt app. · **Don't use when:** You are on React — it is Vue-only despite the "Nuxt optional" framing.
- **Scores /5:** visual 4 · interaction 4 · a11y 4 · engineering 4 · maintenance 5 · docs 5 · customization 4 · perf 4 · stability 4 · originality 3
- **Evidence:** ★6,905 · last release v4.11.1 2026-09-07 · last push 2026-09-09 · 489,856 wk npm · 367 contributors · MIT · 257 open issues. `reka-ui` itself does 1,642,696 wk npm.

That green is the single loudest tell; a Nuxt UI app that ships with `primary: green` is instantly identifiable. The docs pages themselves are among the best-organised in this file.

### HeroUI v3 (ex-NextUI) — `strong`
- **What:** React system on React Aria + Tailwind, now branded "hero", with a paid Pro tier and a React Native line.
- **Verdict:** The prettiest defaults in the category, and the hardest house style to escape. The tagline is literally "Beautiful by default. Customizable by design," and the first half is much truer than the second.

- **Scores /5:** visual 4 · interaction 5 · a11y 4 · engineering 4 · maintenance 4 · docs 4 · customization 3 · perf 3 · stability 4 · originality 2  *(visual 5→4, originality 3→2 after screenshotting it myself — see Looked at. Component-level polish is a 5; the aesthetic being polished is a borrowed and aging one.)*
- **Evidence:** ★30,621 · last release v3.2.4 2026-08-07 · last push 2026-09-09 · 497,047 wk npm (`@heroui/react`) · 234 contributors · Apache-2.0 · 31 open issues
- **Looked at (screenshotted 2026-09-09, 1440 + 390):** `heroui.com` — pill buttons in #006FEE, `flat` variants as tinted pastel pills, gradient-mesh avatar circles, OTP boxes, grey "Continue with Google / Apple" pills, a 20px-radius soft card. ### Ant Design v6 — `situational`
- **What:** Alibaba's enterprise React system; v6 shipped in 2026 with a new masonry component and continued token/CSS-in-JS theming.
- **Verdict:** For dense back-office software — tables with 20 columns, tree-selects, transfer lists, cascaders, form arrays — nothing in the West matches its coverage or its behavioural correctness. It is also one of the most recognisable design languages ever shipped: #1677ff, 6px radius, 32px control height, that specific form-label alignment. Products built with it are identifiable at a glance, and it carries a strong CN-enterprise cultural register that reads wrong in most Western consumer contexts. ### Basecoat UI — `experimental`  *(added 2026-09-09)*
- **What:** shadcn/ui's component vocabulary and token contract rebuilt as plain CSS classes over Tailwind, with small vanilla-JS behaviours. No React, no build step beyond Tailwind.
- **Verdict:** This fills the file's most obvious hole. The original recommended daisyUI as the answer for Rails/Laravel/Django/HTMX while noting daisyUI has "no focus management, no portal, no roving tabindex." Basecoat is the same non-React proposition with actual interactive behaviour attached and — crucially — it is token-compatible with shadcn, so a shadcn theme drops straight in and a team can run a Rails app and a Next app off one token file. 4,287 stars in 20 months and 19,889 weekly downloads is small but it is the fastest-growing thing in the non-React half of this category, and it surfaced through HN and X rather than through listicles, which is why the original pass missed it.
- **Use when:** Server-rendered stacks that want shadcn's design language, or a polyglot codebase that needs one token contract across React and non-React surfaces. · **Don't use when:** You need a large component surface, or the project's youth is a risk you cannot carry.
- **Scores /5:** visual 3 · interaction 3 · a11y 3 · engineering 3 · maintenance 3 · docs 3 · customization 5 · perf 5 · stability 2 · originality 2
- **Evidence (verified 2026-09-09):** ★4,287 · last push 2026-07-21 · 19,889 wk npm (`basecoat-css`) · MIT · 34 open issues · created 2025-01-16
- **Looked at:** Not screenshotted in this pass. Added on verified stats; visual score provisional.
- **Vibecode risk:** **high**, and deliberately so — it reproduces shadcn's default look on purpose. The four escapes in the shadcn scorecard apply verbatim, and they are cheap here because it is all CSS variables.
- **Link:** https://basecoatui.com

## Rejected / avoid
- **Arco Design** — Requesting their own English components-overview route returned a **404 Not Found** page (with the sidebar intact, so the shell renders and the route is broken). 5,698★, 374 open issues, 35,798 wk npm, 116 contributors. ByteDance maintains two competing systems and Semi gets the attention. If you want a CN-lineage enterprise system, use Ant Design; if you want Semi's aesthetics, accept Semi's Chinese-first docs. Arco is the worst of both.
- **Joy UI** — *(version corrected 2026-09-09)* npm `latest` is **`5.0.0-beta.52`, published 2025-03-18** — not beta.49, and eighteen months without a publish — on 101,857 weekly downloads. MUI's engineering went to Base UI and Material UI v9; Joy's templates page still credits "Designed by Untitled UI" and links a 2026 developer survey rather than a roadmap. Never start a project on a system that has been in beta for three-plus years while its parent org ships two other products.
- **Bootstrap 5** — *(re-verified and partly softened 2026-09-09)* Last release **v5.3.8, 2025-08-26** — confirmed, 12.5 months, this corpus's own red-flag threshold. But the earlier framing implied neglect, and the repo does not support that: **last push 2026-09-09**, 174,756★, only 233 open issues, and 5,626,392 weekly npm downloads — the second-most-installed thing in this file after Base UI. It is actively worked on and not shipping. I could **not verify** the `6.0.0-alpha1` / `v6-dev` branch detail from the tag list; treat that specific claim as unverified. The `avoid` verdict stands on **design** grounds, which the rendered dashboard settles, not on abandonment. I rendered their canonical dashboard example: #0d6efd links on every nav item, 4px radius, a sharp-cornered outline button group, and a zebra-striped table — a 2013 layout with a 2021 colour. An agent that reaches for Bootstrap in 2026 is producing dated UI on purpose. (The exception: server-rendered legacy apps already on it. That is maintenance, not selection.)
- **Kuma UI** — 1,859★ and last push 2026-05-29, so it is not abandoned, but **433 weekly npm downloads** is a dead ecosystem by any measure. Zero-runtime CSS-in-JS was a smart idea that Tailwind v4 and Panda made unnecessary. Do not build on it.
- **"Just use MUI because it's popular"** — Not a library, but the most common wrong decision in this category. 8.9M weekly downloads measure 2018–2022 distribution, not 2026 design quality. MUI's own docs confirm it implements Material Design 2. Weigh distribution and taste separately.

## What surprised me
- **shadcn/ui switched its default primitive from Radix to Base UI in July 2026**, and the migration path is an AI skill rather than a codemod — explicitly because a codemod would clobber user customisations. Both primitives stay supported. Most engineers still think of shadcn as "Radix + Tailwind"; for new projects that is now wrong.
- **Two of the best-looking shadcn products contain no shadcn branding, and one contains no shadcn at all.** Midday's `packages/ui` is the exact shadcn component roster (verified: accordion, alert-dialog, avatar, button, calendar, card, carousel, checkbox, collapsible, combobox, command, context-menu, dialog…) plus three shadcn references — yet it reads as a serif-display, zero-radius, warm-neutral editorial product. Dub built `@dub/ui` on Radix + `class-variance-authority` directly with **zero** shadcn references. The lesson: type + radius + ground colour + not-everything-in-a-Card is the entire escape, and it is worth more than switching libraries.
- **shadcn now ships three primitive families and eight named styles — 26 `style` values.** Verified against `ui.shadcn.com/schema.json` on 2026-09-09: the enum is `default`, `new-york`, then `radix-*`, `base-*` and **`aria-*`** (React Aria — a third primitive nobody is talking about) each crossed with vega, nova, maia, lyra, mira, luma, sera, rhea. `components.json` also gained `rtl`, `iconLibrary`, `menuColor`, `menuAccent` and `registries`. Anyone describing shadcn as "Radix + Tailwind + zinc" is two years out of date. *(The earlier claim that `baseColor` accepts mauve/olive/mist/taupe could not be confirmed — the published schema types `baseColor` as a bare string with no enum. Treat it as **unverified**; the `style` enum above is the verified and more consequential version of that finding.)*
- **shadcn has a public registry index with health scoring, and it lists 294 third-party registries.** `ui.shadcn.com/r/registries.json` returns 294 entries — @aceternity, @animate-ui, @assistant-ui, @8bitcn and 290 more — each carrying a `health` object with a status and a reason. shadcn stopped being a component library and became a package index for design languages, with the monoculture problem partly outsourced to whoever you point it at.
- **Nuxt UI Pro stopped being a paid product.** After NuxtLabs joined Vercel, v4 merged Pro into the free MIT `@nuxt/ui`: 110+ components, 12 templates, and a 2,000-variant Figma kit, all free. Any recommendation that still says "Nuxt UI Pro costs money" is stale.
- **Park UI is now inside the Chakra UI GitHub org**, its site footer reads "© 2025 Chakra Systems", and `@park-ui/panda-preset` has not published since November 2024. It has the best neutral defaults in this file and is effectively a design reference now, not a dependency.
- **Vuetify shipped an unstyled primitive layer.** `@vuetify/v0` hit 1.0 in July 2026 and v3 went LTS through July 2027. The Material-for-Vue flagship building a headless escape hatch is the clearest signal in this file that the styled-kit era is ending in favour of primitives-plus-your-tokens.
- **`react-aria-components` does 3,520,784 weekly npm downloads** — more than `antd` (3,199,837) and roughly 39% of `@mui/material` (8,924,416). *(Corrected 2026-09-09: the earlier line also said "more than every Vue system combined." That is false once `reka-ui` is counted — vuetify 905,416 + primevue 762,547 + @nuxt/ui 489,856 + reka-ui 1,642,696 = **3,800,515**, which is more. It holds only if you exclude reka-ui, and excluding the primitive while making a point about primitives is not a fair comparison.)*
- **The biggest number in this file is a primitive, and the original pass was off by 25x.** `@base-ui/react` does **10,994,876 weekly downloads** — more than `@mui/material`, more than `antd`, more than every styled kit here combined. The original recorded 429,187 because it queried `@base-ui-components/react`, the pre-1.0 package name, which is frozen at `1.0.0-rc.0` (2025-12-04). The lesson generalises: a renamed package makes a healthy project look dead, and it is the single easiest way for a research pass like this one to be confidently wrong.
- **The GitHub Releases tab is not the release history, and trusting it produced two wrong verdicts here.** Semi Design was written off for a "ten-month release gap" that never happened — npm shows `2.103.0` on 2026-09-01 and the git tags agree; only the Releases *feed* stopped at v2.88.2. PrimeVue was faulted for a "five-month cadence problem" while it was shipping v5.0.0 (2026-07-15). Check npm `dist-tags` and git tags before calling a project stale.
- **Untitled UI React's component library is deliberately unpublished, and its icon set out-ships it 62:1.** The repo's own `package.json` is `"private": true` at version `0.0.0`. Distribution is the `untitledui` CLI at **4,913 weekly downloads** — fewer than Once UI, which this file called adoption-thin — while `@untitledui/icons` does 304,138. The stars measure design admiration; they do not measure use.
- **Radix Themes does 878k weekly downloads and has not been pushed since April 2026.** A styled system with more adoption than Nuxt UI or HeroUI went quiet five months ago and nobody wrote it up. Worth watching: it is WorkOS's, and shadcn has already moved its default primitives elsewhere.

## Open questions
- ~~**PrimeReact's release channels disagree**~~ — **settled 2026-09-09.** `10.9.9` was published to npm on 2026-08-27, *after* `11.0.0` (2026-07-15) and `11.1.0` (2026-08-05). It is a backport to the v10 line; the Releases feed sorts by date and surfaces it on top. Release hygiene is fine.
- **PrimeReact's enterprise logos** (Volkswagen, Intel, UniCredit, Lufthansa) are their marketing claim; I found no independent confirmation. Same for Semi Design's "nearly a thousand platform products / 100k+ users" and the "Trusted by OpenAI, Sonos, Adobe" line in Vercel's shadcn deploy card (which describes Vercel's customers, not shadcn's). All **unverified**.
- ~~**Untitled UI React's distribution model**~~ — **settled 2026-09-09.** The repo's `package.json` declares `"private": true` at version `0.0.0`: the package is never published, by design. Adoption *is* measurable, via the `untitledui` CLI (4,913 wk) and `@untitledui/icons` (304,138 wk). The stars overstate usage substantially. This drove the demotion to `situational`.
- **Whether Ant Design v6 finally moved off runtime CSS-in-JS.** v5's `@ant-design/cssinjs` was a measurable SSR and hydration cost; I did not verify what v6 changed. Settled by reading the v6 migration guide and measuring a cold SSR render.
- ~~**Whether Semi Design's ten-month release gap is a pause or an exit.**~~ — **settled 2026-09-09: neither, because there was no gap.** npm has `2.100.0` → `2.103.0` shipping monthly through 2026-09-01, and the git tags match. Only the GitHub Releases feed stopped. Semi promoted to `situational`.
- **Why Radix Themes has been silent since 2026-04-11** while doing 878k weekly downloads. Maintenance mode under WorkOS, a rewrite in progress, or attrition? Settled by reading the `main` branch commit log and any WorkOS engineering post; it changes whether the `situational` tier should be `reference-only`.
- **Whether shadcn's eight named styles reduce or relocate the monoculture.** With 26 `style` values and 294 third-party registries, does AI-generated shadcn output actually diversify, or does everything still land on `new-york`? Settled by sampling what v0/Lovable/Cursor emit for `shadcn init` in practice — the most decision-relevant open question in this file for an anti-vibecode corpus.

Their visual scores are provisional and flagged as such in each entry.

## Challenge pass (2026-09)

Adversarial re-verification run **2026-09-09**. Every `essential` and `strong` entry was re-checked against the live GitHub and npm APIs; four interfaces were screenshotted fresh at 1440 and 390 (`untitledui.com/react`, `park-ui.com`, `heroui.com`, `radix-ui.com/themes`) and judged independently of the original notes.

**What held up.** Most of it. shadcn/ui, Mantine, Chakra v3, Nuxt UI, HeroUI, Ant Design, daisyUI, Park UI, Fluent, MUI, Vuetify, Flowbite, Once UI, Skeleton, Arco and Kuma UI all matched to the digit — stars, weekly downloads, contributor counts, issue counts, release dates. Mantine's 58-issues-on-31.7k-stars, MUI's Material-Design-2 callout, Once UI's 6,837 weekly, Kuma UI's 433 weekly and Bootstrap's 2025-08-26 last release are all real. The core thesis — that this category has split into copy-in registries, npm-installed systems and legacy sets on inertia, and that shadcn's defaults are the visual signature of AI-generated UI — survives intact.

**Five numbers were wrong.**
1. **Base UI: 429,187 → 10,994,876 wk npm.** The original queried `@base-ui-components/react`, renamed at 1.0 and frozen at `1.0.0-rc.0` (2025-12-04). The live package is `@base-ui/react` v1.8.0. A 25x understatement.
2. **Semi Design was not stale.** "No release since v2.88.2, November 2025" was read off the GitHub Releases feed. npm and the git tags both show monthly releases through **2.103.0 (2026-09-01)**.
3. **PrimeVue was not stalled.** "Last release 4.5.5, April 2026" missed **v5.0.0 (2026-07-15)** and 5.0.1 (2026-08-13).
4. **Joy UI is at `5.0.0-beta.52` (2025-03-18)**, not beta.49.
5. **"react-aria-components does more than every Vue system combined"** is false once `reka-ui` (1,642,696) is counted: the Vue total is 3,800,515 against RAC's 3,520,784.

Two claims are now marked **unverified** rather than dropped: shadcn's `baseColor` accepting mauve/olive/mist/taupe (the published schema types it as a bare string with no enum), and Bootstrap's `6.0.0-alpha1` on a `v6-dev` branch (not present in the tag list). Bootstrap's `avoid` verdict was also re-grounded — the repo is pushed daily, has 233 open issues and does 5.6M weekly downloads, so the case against it is design and release cadence, not neglect.

**Two tiers moved.**
- **Base UI `strong` → `essential`.** At 11M weekly it is the most-installed thing in the file and the default substrate under the category leader. Its maintenance score went 5 → 4: 435 open issues, which the original scorecard did not record at all.
- **Untitled UI React `strong` → `situational`, vibecode risk medium-high → high, visual 4 → 3, originality 3 → 2.** Three grounds. Its real distribution is the `untitledui` CLI at **4,913 weekly downloads** — *below* Once UI's 6,837, which this file called "brutal" and used to justify `experimental`; applying the file's own standard consistently required the move. The MIT library is a funnel for a $349 kit, which is the exact incentive read used to put Flowbite at `reference-only`. And on screenshotting it, the site is the canonical 2023–2025 SaaS template — white ground, dotted grid, centred grotesk, violet CTA, tilted screenshot stack, fake "Olivia Rhye" cursor — which is the look AI page-builders emit by default. Component craft is genuinely good and that is preserved in the a11y and interaction scores; the composition was inherited praise.
- **Semi Design `experimental` → `situational`** on the correction above (maintenance 2 → 4, stability 3 → 4).
- **HeroUI visual 5 → 4, originality 3 → 2.** Not a tier change — `strong` and "best out-of-box polish" both survive. But the screenshot does not support "prettiest in the category": it is Apple's HIG as of roughly 2023, and the pastel-flat-pill idiom has aged. The vibecode note now says so, because "dated" is a worse outcome for most teams than "AI-looking" and the original did not name it.
- **Park UI keeps visual 5** — the strongest claim in the original file and it survives inspection; the demo cards use real content and honest field spacing where shadcn's blocks use placeholders. Two small corrections: the radius reads 8–10px not 6px, and the cards do carry soft shadows, so "no shadow theatre" overstated it.

**Popularity bias found, in both directions.** Downward: the original dismissed Once UI for 6.8k weekly downloads while tiering Untitled UI `strong` at 4.9k — the difference was that one is famous among designers. Upward: Base UI's real number was never checked because 429k looked plausible for a young project. And the category was surveyed through a React-first, English-first lens — `@angular/material` does 2.1M weekly and Angular did not appear at all; Element Plus has more stars and more downloads than Nuxt UI and did not appear either.

**Eight additions.** Missing entirely, all verified live on 2026-09-09: **React Spectrum** (`strong`, 1.03M wk — the file credited React Aria's a11y to two downstream libraries while omitting the one Adobe ships), **Radix Themes** (`situational`, 878k wk, silent since 2026-04-11 — the most conspicuous omission), **Angular Material** (`situational`, 2.1M wk) and **Spartan UI** (`experimental`) filling a total Angular gap, **Element Plus** (`situational`, 27.7k★ / 618k wk), **Basecoat UI** (`experimental`, the non-React shadcn the file's own daisyUI caveat called for, surfaced on HN/X rather than listicles), plus **Carbon**, **Web Awesome**, **Quasar** and **Naive UI** verified and noted without full scorecards. Only Radix Themes was screenshotted; the other visual scores are flagged provisional.

**Vibecode column hardened.** A note at the top now separates the two axes the original conflated: how identifiable the default is, versus whether you can escape it — the second is governed by distribution model, not taste, which is why `high (as shipped) / low (after N changes)` on a copy-in system is a completely different risk from a flat `high` on an npm dependency. Untitled UI moved to `high`. HeroUI's note now says the look is aging, not merely strong. Basecoat is marked `high` on purpose. And a sixth escape was added to the shadcn fix list — with 26 `style` values now available, do not init on `new-york`, while being honest that this moves you to a smaller shared fingerprint rather than to originality.

**Verification method.** `gh api repos/OWNER/REPO` for stars, pushes, issues, licences and release feeds; `gh api .../tags` where the Releases feed was suspect; `api.npmjs.org/downloads/point/last-week/PKG` for downloads; `registry.npmjs.org/PKG` for `dist-tags` and per-version publish timestamps; `ui.shadcn.com/schema.json` and `/r/registries.json` for the shadcn claims; `tools/shot.mjs` at 1440 and 390 for the four visual re-reads.
