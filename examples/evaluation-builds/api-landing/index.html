The four documents that break a parser

Not the clean ones. These four account for most of the tickets we get, so here is what Folio does about each, including the one we still hand back unfinished.

A table that continues onto page 3

We stitch rows on column geometry, not on a repeated header, because rent rolls and detention logs usually drop the header after the first page. Continuation rows carry the same table_id and their own page.

A 200 dpi fax of a photocopy

Deskew, then a second pass at 2× on any region that came back under 0.60 confidence. It costs about 400 ms per page and recovers roughly a third of them. The rest stay flagged rather than guessed.

Labels above values, in two columns

Reading order comes from the whitespace gutter, not from the y-coordinate, so Policy no. does not pick up the value sitting next to it in the other column. This is the single most common silent error in every parser we tested, ours included, until we changed it.

Handwriting

We return it, flagged: confidence: 0.71, review_required: true. We would rather hand you a number to check than a number to trust. If your workflow cannot route a review, filter on that flag and drop the field.

What Folio does not do

No e-signature. No classification model you can fine-tune yourself yet. No Zapier app. Documents and their extractions are deleted 24 hours after the last read, which means there is no re-parse of last month’s file and no training on your data. If you need retention, you store it.
